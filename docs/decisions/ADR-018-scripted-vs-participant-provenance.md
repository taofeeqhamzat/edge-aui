# ADR-018: Scripted vs Participant Provenance and the Egress Boundary

- **Status:** Accepted — **amends ADR-009, ADR-010 and `AGENTS.md` §2**
- **Date:** 2026-10-02
- **Related:** ADR-013, ADR-015, ADR-017, ADR-022, ADR-023

## 1. Context

Two constraints that were previously unambiguous now conflict, and the conflict has to be resolved
deliberately rather than absorbed.

**`AGENTS.md` §2 stated:** "All behavioral data must be processed locally; no telemetry may be
transmitted to external servers."

**ADR-009 recommended:** local persistence, "no upload path at all".

**`docs/architecture.md` §11 claimed:** "Zero Network Egress: No network primitives are reachable or
called during telemetry processing or model inference."

**The supervisor-ready brief requires (§8, §17):** a durable collection path where a completed
session reaches Supabase, retrieved and exported for dataset preparation.

At the same time, ADR-013 already fixes a boundary the project must not cross:

```text
synthetic
scripted browser session
generated by deterministic policy
not participant ground truth
```

The audit found that boundary being violated in prose: `sparse-window-loss.md` described six "real
participant traces" that are scripted substitute data with `participantId: null`, and the headline
condition comparison presented hand-authored fixtures as runs (assessment F-12).

## 2. Problem

What may leave the client, under what condition, and how is that condition enforced rather than
documented?

## 3. Options considered

| Option | Description | Effect |
| --- | --- | --- |
| **A. No egress at all; local only** | Restore the pre-existing guarantee | Contradicts the brief's collection requirement; collection does not exist |
| **B. Upload any trace; record provenance as metadata** | One upload path, provenance as a label | Participant telemetry would egress before any consent workflow exists; the label would be advisory |
| **C. Provenance gates egress** | Upload permitted only for provenance allowed by the build's configured collection mode | Upload exists; the boundary is enforced in code |

## 4. Evidence available

**Verified:** `grep` over `src/` found zero network primitives before this change. After it,
`tests/collection_persistence.test.ts` asserts that an unconfigured build makes **zero** network
calls, that a `participant`-provenance session in `scripted` collection mode makes **zero** network
calls, and that the same session uploads only when the mode explicitly permits it.

**Verified:** the model- and runtime-asset loads are same-origin static-file requests, so the earlier
absolute claim ("no network primitives during model inference") was already imprecise — assessment
F-26. The substantive property (no behavioural data leaves the client) held; the phrasing did not.

## 5. Decision required

Whether egress is permitted, for which data, and what enforces it.

## 6. Decision

**Option C. `provenance` is an enforcement switch, not a label.**

- `SessionContext.provenance` is `'scripted' | 'participant'` and **defaults to `'scripted'`**. It is
  never inferred from behaviour, timing or absence.
- `VITE_AUI_COLLECTION_MODE` selects what a build may upload: `off`, `scripted` (default) or `all`.
  `mayUploadProvenance()` is the single decision point; `ResearchCollection` calls it before any
  request is constructed.
- In the default `scripted` mode a participant-provenance trace is recorded locally, exported
  normally, and **refused for upload** with a reason that distinguishes the refusal from a network
  failure.
- `participantId` is optional, nullable, and never populated by the testbed. No participant
  identifier scheme has been approved (ADR-023), and inventing one would create a
  re-identification surface nobody agreed to.

### What this amends, explicitly

**`AGENTS.md` §2** — the absolute prohibition is replaced by the provenance-gated rule: no
behavioural telemetry egress except explicit, provenance-gated research collection, which awaits a
consent workflow before it accepts participant data.

**ADR-010 Guarantee 2** — "Zero Network Egress" becomes "no behavioural-telemetry egress beyond the
provenance-gated research collection path; model and runtime assets are loaded as same-origin static
files." The guarantee's substance is preserved; the absolute wording was not accurate even before
this change.

**ADR-009** — the "no upload path at all" recommendation is superseded by ADR-015.

### Consequences

- Participant data cannot reach the store through configuration alone; enabling it requires passing
  `'all'` to the gate, which is a deliberate, reviewable action.
- Provenance travels in three places so it cannot be lost: `session.provenance`, `metadata.provenance`
  and a `provenance` column on the canonical event schema in `model-preparation`, so scripted and
  participant records cannot be pooled by accident.
- A trace with no valid provenance is a verification failure, not a default. The verifier gained a
  `provenance_declared` check.
- The local store is itself new participant-side persistent storage, so ADR-010's "No Local
  Persistence" clause is also superseded; this is recorded in ADR-019.

## 7. What is being deferred

> **Decision:** Enabling participant collection at all.
> **Deferred until:** An approved research protocol, an ethics position, a consent/withdrawal flow
> and a retention policy exist.
> **Reason:** The brief's scope boundary defers the participant consent system, and no protocol is
> approved.
> **Current workaround:** Scripted traces only, labelled as such throughout.
> **Risk:** Low while collection remains scripted-only; the risk of enabling it early is that
> participant data is collected without a lawful basis.
> **Evidence required to revisit:** Written protocol approval plus a consent mechanism.

> **Decision:** A participant identifier scheme.
> **Deferred until:** The protocol defines what has to be linked across sessions.
> **Reason:** The identifier's shape follows the analysis requirement; choosing it now would invent
> personal data the study may not need.
> **Current workaround:** `participantId` is `null`; sessions are linked only by anonymous session
> id.
> **Risk:** Low — no participant data exists yet.
> **Evidence required to revisit:** A protocol requirement for cross-session linkage.

## 8. Conditions that would force this decision to be revisited

- Any artifact describes scripted traces as participant evidence — the boundary has failed and must
  be restated more forcefully.
- A participant study is scheduled, which requires the consent and retention workflow first.
- An institutional review requires a different egress or storage posture.
