# Task 20.3 — Configurable Gate Vocabularies

## Description

Remove hardcoded class orders from the gates:

- `OnnxSlowGate` reads the outcome vocabulary/order from model manifest/config;
- Fast Gate patterns map to normalized semantic outcomes, not only intervention commands;
- the old five-class intervention head remains loadable as a compatibility artifact;
- vocabulary/version identity travels with the prediction.

## Acceptance criteria

- [ ] `OUTCOME_CLASS_ORDER` and `TARGET_INTERVENTION_ORDER` are no longer required by the semantic
      path; the configured vocabulary/order is supplied by model metadata/config.
- [ ] The Slow Gate validates the model output dimension against the configured vocabulary and
      fails visibly on mismatch.
- [ ] Fast Gate pattern configuration accepts a semantic outcome ID (and optional confidence) and
      returns a normalized prediction; existing intervention-pattern configuration remains
      supported during migration.
- [ ] The model manifest/config carries vocabulary, vocabulary version and model version; the
      prediction records them.
- [ ] Old `model_int8.onnx` / `intervention_head_int8.onnx` paths still load in compatibility mode;
      the new semantic head path is configurable.
- [ ] Tests cover vocabulary mismatch, configured order mapping, fast pattern→outcome mapping and
      legacy compatibility.
- [ ] `npm test` and `npm run typecheck` pass.
