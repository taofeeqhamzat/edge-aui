# Task 20.2 — Application Vocabulary Boundary

## Description

Move the application-specific vocabulary out of framework core:

- macro symbol vocabulary and event→symbol mapping;
- route vocabulary and task step counts used by context encoding;
- declared Fast Gate patterns currently in `src/runtime/boot.ts`.

Introduce generic contracts and testbed implementations/configuration. The framework must work with
a different application's pages, actions and tasks without core edits.

## Acceptance criteria

- [ ] A `MacroMapper` contract exists; the testbed supplies the symbol vocabulary and
      event→symbol rules. Framework sequence/stream code accepts the mapper rather than importing
      testbed IDs.
- [ ] A `ContextEncodingConfig` accepts route vocabulary, action vocabulary and task step
      counts/totals. The testbed supplies its routes and TD1–TD4 step counts; core has no
      `Analytics`/`Reports`/`TD1`–`TD4` constants.
- [ ] Testbed Fast Gate patterns move out of `src/runtime/boot.ts` and are injected by the testbed
      composition/configuration.
- [ ] A second mock adapter with a different route/action/task vocabulary produces a valid context
      vector and macro stream without importing testbed modules.
- [ ] Existing `getActiveUIContext`, macro tests and context-vector tests pass with the testbed
      configuration.
- [ ] A source check/grep confirms no testbed route/task IDs remain in framework core modules.
- [ ] `npm test` and `npm run typecheck` pass.
