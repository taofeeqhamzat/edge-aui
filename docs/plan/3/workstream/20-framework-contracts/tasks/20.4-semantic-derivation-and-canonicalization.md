# Task 20.4 — Semantic Derivation and Canonicalization

## Description

Add the generic canonical event pipeline and application-supplied semantic outcome derivation:

- committed `change` only when the value actually changed;
- one checkbox interaction → one selection;
- one form submission → one `apply_filter` (suppress duplicate click);
- one date commit → one date outcome;
- exact identifier/role checks before substring checks;
- system/programmatic actions excluded from user outcomes;
- semantic outcome rules supplied by the testbed;
- route-level backtracking seeded from the starting page.

The generic seven-class `OutcomeDeriver` remains for backward compatibility.

## Acceptance criteria

- [ ] A generic canonical-action layer exists and is shared by the task bridge and semantic
      derivation; it does not delete the raw event.
- [ ] `change`/`input`/`submit` are recognised; `btn-export` is not `FORM_SUBMIT`; `blur` is not
      `BACKTRACK`.
- [ ] Exact role/ID matching wins: `tooltip-region` is `inspect_help`/not `select_region`; row
      hover is not row selection.
- [ ] The testbed supplies semantic rules for the approved vocabulary; the framework core imports
      no testbed outcome IDs.
- [ ] `apply_filter` comes from a form submit, not a generic button click; `export_report` is
      distinct; report open is `select_report`, not `navigate_analytics`.
- [ ] Backtracking: `visitedPages = [startingPage]`; deliberate page change to a previously visited
      page emits `backtrack`; same-page clicks, blur, accordion collapse and filter edits do not.
- [ ] A semantic outcome is recorded alongside the generic outcome; both remain in the trace.
- [ ] Fixture tests cover every approved vocabulary rule and the negative cases.
- [ ] `npm test` and `npm run typecheck` pass.
