# Task 60.1 — Outcome Policy and Target Resolution

## Description

Implement the testbed's semantic outcome→intervention policy and the target-resolution contract:

- map predicted outcomes + UI context to candidate interventions;
- keep the generic policy gates (confidence, persistence, context, cooldown, dismissal, TTL,
  per-task limit);
- resolve targets through the application resolver;
- define missing-target behavior and record actuation failure.

## Acceptance criteria

- [ ] A testbed policy maps the approved semantic outcomes to candidate interventions; unmapped/
      ambiguous outcomes fall back to `no_op`.
- [ ] Confidence/context/cooldown/dismissal/TTL/limits remain enforced; repeated predictions do not
      produce repeated interventions.
- [ ] The `simplify_options` target is supplied by configuration, not hardcoded in framework core.
- [ ] Missing target → no mutation, explicit actuation failure and policy record.
- [ ] Baseline condition remains decision-only and never applies an adaptation.
- [ ] `expand_tooltip` uses real title/data-tooltip text; no generic fallback target.
- [ ] Tests cover mapping, conservative suppression, cooldown/TTL, missing target and baseline.
- [ ] `npm test` and `npm run typecheck` pass.
