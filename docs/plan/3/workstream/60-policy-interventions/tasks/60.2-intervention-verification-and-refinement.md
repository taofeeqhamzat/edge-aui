# Task 60.2 — Intervention Verification and Refinement

## Description

Verify every in-scope intervention type functionally and visually, refine styling/behavior where
necessary, and produce an evidence report that distinguishes visual verification from source/unit
verification.

## Acceptance criteria

- [ ] `highlight_primary_action`, `simplify_options`, `expand_tooltip`, `offer_assistance` and
      `no_op` are each exercised on a real rendered target.
- [ ] For each: correct target, visible state, no layout shift that disrupts interaction, no focus
      theft, dismiss/cleanup works, no unintended DOM mutation, no duplicate episode.
- [ ] Baseline condition applies no adaptation; adaptive condition applies only configured policy
      actions.
- [ ] Missing target is tested for each applicable type; no random fallback mutation.
- [ ] Intervention does not prevent task completion or corrupt the accessibility tree.
- [ ] Screenshots at the intended viewport(s) are captured for each type; a human-reviewable report
      records what was visually verified.
- [ ] Refinements are limited to visibility/style/placement/dismissal; no task redesign.
- [ ] The report lists visually verified vs source-only items.
- [ ] `npm test` and `npm run typecheck` pass.

## Verification

```bash
cd edge-aui-framework
npm test -- tests/actuator.test.ts tests/condition_trace_comparison.test.ts tests/intervention_types.test.ts
npm run typecheck
```

Then run the deployed/preview testbed, trigger each configured intervention, and capture screenshots.

## Dependencies

- 60.1 outcome policy and target resolution.

- `src/intervention/actuator.ts` (only if verification finds a defect)
- `src/testbed/policy/outcomePolicy.ts`
- `tests/actuator.test.ts`
- Verification report/screenshots under `docs/plan/3/workstream/60-policy-interventions/`

## Estimated scope

Medium — verification suite, screenshots, report; limited UI/CSS edits.

## Notes

- Do not claim an intervention is useful or improves task performance; only mechanism/visibility
  is verified here.
- `simplify_options` collapses options; verify it does not make a required task step impossible.
- TTL/dismissal behavior must be observed, not inferred from the command type.
