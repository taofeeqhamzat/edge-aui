# Task 50.2 — Pattern Semantics and Semantic Mapping

## Description

Define and test the Fast Gate pattern configuration and semantics:

- declaration format and validity;
- minimum support, min/max pattern length, confidence/strength;
- sequence boundaries and session isolation;
- pattern→semantic outcome mapping;
- no-match behavior and reasons.

## Acceptance criteria

- [ ] Pattern definitions are validated (non-empty sequence, known symbols, valid target outcome,
      confidence range, support/length bounds).
- [ ] Session/sequence boundaries prevent patterns from spanning unrelated sessions or tasks.
- [ ] A pattern match returns a normalized semantic prediction with pattern provenance and
      confidence/strength.
- [ ] No-match returns `matched: false` with a reason; it does not fabricate a prediction.
- [ ] The declared pattern set is aligned to TD1–TD4 canonical paths; canonical paths do not emit
      false matches.
- [ ] Existing intervention-pattern configuration remains readable during migration.
- [ ] Deterministic tests cover declaration validation, boundary/session isolation, mapping and
      no-match.
- [ ] `npm test` and `npm run typecheck` pass.

## Notes

- Patterns are application configuration; do not hardcode testbed sequences in framework core.
- A high match confidence is not proof of user benefit; it is a gate result only.
- Do not expand the Fast Gate into a "known-good sequence" whitelist; it is a frequent-pattern
  miner with explicit support/confidence.
