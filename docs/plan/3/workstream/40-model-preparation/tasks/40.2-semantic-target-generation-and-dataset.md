# Task 40.2 — Semantic Target Generation and Dataset v2

## Description

Add semantic target generation and a versioned semantic dataset:

- future semantic outcome labels from the trace's semantic outcomes and/or deterministic
  re-derivation;
- committed change/form-submit/report/reset/navigation rules matching the TypeScript layer;
- provenance for each label and vocabulary version;
- retained generic `target_outcome`/intervention columns for legacy/ablation;
- session/task-aware dataset assembly without leakage.

## Acceptance criteria

- [ ] A semantic target module derives the approved 14 target outcomes (plan §3.4) from events
      after the anchor window within the configured horizon.
- [ ] The rules mirror the TypeScript semantic layer on shared fixtures: committed change, form
      submit, report selection, reset, navigation/backtrack, ignore hover/substring/system actions.
- [ ] `TARGET_DATASET_SCHEMA` v2 adds `target_task_outcome`, `target_task_outcome_id`,
      `target_vocabulary_version`, `recorded_vocabulary_version`, `task_definition_version` and
      label provenance; existing generic columns remain.
- [ ] Dataset version is explicit (for example `v2.0.0-semantic`); the old v1.0.0 dataset is not
      overwritten.
- [ ] Every example retains the required provenance fields and its source event IDs.
- [ ] Windows whose future outcome is `inspect_help` are excluded from the label set, never
      relabelled `NO_OUTCOME`, and the excluded count is reported per partition
      ([ADR-030](../../../../../decisions/ADR-030-semantic-target-vocabulary-pinned-to-14.md)).
- [ ] Tests cover label correctness, boundary conditions, missing semantic outcome, the
      `inspect_help` exclusion, provenance and schema.
- [ ] The dataset can be built from the scripted captures; this is a pipeline result, not
      participant evidence.
- [ ] `python3 -m pytest tests -q` passes.
