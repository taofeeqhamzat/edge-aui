# Task 40.4 — Semantic Target-Head Training and Evaluation

## Description

Train a new target head on the semantic outcome vocabulary using participant traces, while
preserving the foundation GRU and the previous five-class intervention head as reproducible
artifacts.

**This task is blocked until usable participant traces exist.** Scripted traces can smoke-test the
pipeline but cannot satisfy the evaluation acceptance criteria.

## Acceptance criteria

- [ ] A semantic target head has output dimension 14 — the approved target vocabulary, not the
      15-ID recorded vocabulary ([ADR-030](../../../../../decisions/ADR-030-semantic-target-vocabulary-pinned-to-14.md))
      — and accepts `(sequence, context)`.
- [ ] The foundation GRU checkpoint is preserved; freeze/partial/full ablation is reproducible.
- [ ] Training config records semantic taxonomy, dataset version, seed, history/horizon, class
      weights and head class count.
- [ ] Evaluation reports per-class P/R/F1, support, macro-F1, weighted-F1, confusion matrix,
      majority baseline, class distribution, task-level results and held-out results at the
      declared split unit (session-held-out until a participant identifier exists;
      [ADR-031](../../../../../decisions/ADR-031-session-bounded-dataset-splits.md)).
      Participant-held-out generalisation is not claimed without an identifier.
- [ ] Prediction lead time and calibration/reliability are reported where support permits.
- [ ] No future data, post-intervention evidence or task-lifecycle label leaks into inputs or
      targets.
- [ ] The previous five-class head/bundle remains unchanged and reproducible.
- [ ] Results distinguish scripted pipeline evidence from participant-derived evaluation.
- [ ] Tests cover output dimension, input contract, no-leakage assertions and metric availability.

## Notes

- Do not relabel the old head; train a new one.
- Do not report semantic-head metrics without stating the dataset, support and held-out protocol.
- If a class has zero support in a partition, report that explicitly rather than a misleading F1.
- The user-experience effect of interventions is a separate evaluation; model accuracy is not
  evidence of user benefit.
