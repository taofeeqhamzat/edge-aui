# Task 40.3 — Window/Horizon Experiment, Splits and Class Balance

## Description

Evaluate a small, pre-declared set of history-window and prediction-horizon configurations for the
semantic vocabulary, then finalize splits and class weights for semantic training.

## Acceptance criteria

- [ ] Four configurations are evaluated (baseline 8×500/250/[500,1500]; 8×500/250/[1000,2000];
      4×500/250/[500,1500]; 12×500/250/[500,1500]) or a documented equivalent small set.
- [ ] For each: per-outcome frequency, time between actions, lead time, per-class P/R/F1,
      macro-F1, class imbalance, false early predictions, incomplete windows.
- [ ] Selection uses pre-declared criteria (coverage + macro-F1 + lead time + stability), not a
      single aggregate; the report explains the choice.
- [ ] Splits are session-bounded: partitions are computed on `session_id` before window
      generation and no session appears in two partitions
      ([ADR-031](../../../../../decisions/ADR-031-session-bounded-dataset-splits.md)). Participant-
      bounded splits are deferred until ADR-023 approves an identifier; the split unit is recorded
      in the manifest.
- [ ] Task-level coverage is reported per partition: tasks present, their example counts and any
      absent task.
- [ ] Class weights are resolved on the training partition only; absent classes are declared.
- [ ] Majority baselines and support are reported for each partition, alongside the excluded
      `inspect_help` window count (ADR-030).
- [ ] Semantic dataset version/manifest records the chosen configuration and class weights.
- [ ] No open-ended hyperparameter search is performed.
- [ ] Tests cover split disjointness, class-weight independence from val/test, and configuration
      reproducibility.

## Notes

- Do not use held-out (validation/test) partitions to select the configuration.
- Do not claim statistical adequacy or a participant count; this is a small controlled experiment.
- Session is the split unit. Do not describe the partitions as participant-held-out; that claim
  requires an approved participant identifier (ADR-031).
- Preserve the old v1.0.0 split/manifest for reproducibility.
