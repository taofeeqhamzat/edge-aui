# Task 10.3 — Task Host, Filter State and Reset

## Description

Make trial starts reproducible and filter state consistent:

- Lift the filter draft state out of `FilterDrawer` into `App` (or make the drawer fully
  controlled), so the applied filters and visible controls cannot disagree.
- Add `Reset Filters` (`btn-reset-filters`) that clears both draft and applied state immediately;
  it must be `type="button"` and must not submit the form.
- Add task-start normalization before `task_start`: set `startingPage`, reset filters, collapse
  sections, clear report/error/evidence/timer state.
- Guard task replacement and condition changes while a task is in progress, or define an explicit
  abandonment transition.

## Acceptance criteria

- [ ] `App` owns the draft and applied filter state; `FilterDrawer` receives and displays the
      current values; applying updates both consistently.
- [ ] Navigating away from Analytics and back leaves the table and drawer showing the same filter
      state.
- [ ] `btn-reset-filters` clears draft + applied filters, collapses sections, and restores 50 rows;
      it does not submit the form or emit `apply_filter`.
- [ ] Starting any task sets the declared page, clears filters/sections/report/errors/timer, then
      emits `task_start`. Task-start routing does not emit a participant navigation outcome.
- [ ] Start buttons and condition controls are disabled while a task is `In Progress`, or a
      replacement/condition change abandons the active trial with the explicit reason before the
      new state begins.
- [ ] Reset Trial clears filters, report state and task evidence, and records abandonment when the
      trial was in progress.
- [ ] Tests cover: navigation consistency, reset, start normalization for all four tasks,
      replacement/condition-change behavior.
- [ ] `npm test` and `npm run typecheck` pass.
