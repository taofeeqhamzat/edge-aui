# Task 10.2 — Task Model v2 and Configuration

## Description

Replace the legacy T1–T3 task definitions with the approved TD1–TD4 model. Add the fields the task
harness needs: `startingPage`, a task-definition version, timeout, canonical steps and a
completion-predicate identifier. Update every configuration map keyed by task ID.

## Acceptance criteria

- [ ] `TaskId` is `TD1 | TD2 | TD3 | TD4`; legacy T1–T3 are removed from the participant UI.
- [ ] Each task definition contains: `id`, `name`, `startingPage`, `definitionVersion`
      (`TD-v2`), `timeoutMs`, canonical `steps` and a completion-predicate identifier.
- [ ] TD1 starts on `Overview`; TD2/TD3 on `Analytics`; TD4 on `Reports`.
- [ ] TD1–TD4 step component IDs exist in the rendered UI before the task is marked implemented:
      TD1–TD3 after 10.1/10.3; TD4 after 10.4. Until then, the TD4 wiring test is marked pending,
      not silently skipped.
- [ ] `TASK_STEP_COUNTS` (context vector), `experiment.trialOrder` and
      `experiment.taskTimeoutsMs` use TD1–TD4. The old T1–T3 keys are removed.
- [ ] `npm test` and `npm run typecheck` pass; component-existence tests reflect the new tasks.
- [ ] No completion predicate is implemented in this task; placeholders are clearly typed and
      resolved in 10.5.
