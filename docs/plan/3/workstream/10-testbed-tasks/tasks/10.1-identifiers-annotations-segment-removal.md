# Task 10.1 — Stable Identifiers, Region Annotations and Segment Removal

## Description

Prepare the testbed's UI contract for TD1–TD4:

1. Normalize the filter-section IDs to stable snake_case IDs.
2. Add `data-aui-region` to the major UI regions.
3. Remove the inert Customer Segment control and its state.
4. Keep `data-aui-component` as the canonical component identifier; do not introduce a parallel
   `data-aui-id` scheme without an approved migration.

This task does not change task definitions or completion logic; it makes the identifiers those
tasks will target stable.

## Acceptance criteria

- [ ] Filter sections use: `filter-section-date-range`, `filter-section-region`,
      `filter-section-product-category`. No space-containing filter-section IDs remain.
- [ ] `taskModel.ts`, task tests, semantic annotation tests and any interim macro mapping references
      are updated to the new IDs.
- [ ] `data-aui-region` is present on the major regions: navigation (`navigation`), trial panel
      (`trial`), page shell (`page`), filter drawer (`filters`), KPI grid (`kpis`), results table
      (`results`) and debug panel (`debug`).
- [ ] The Customer Segment `<select>`, `FilterState.segment`, `EMPTY_FILTER_STATE.segment` and the
      `applyFilters()` segment references are removed. No semantic `select_segment` producer is
      claimed in the testbed.
- [ ] No test or source file still queries `filter-segment-select` or `filter-Product Category` /
      `filter-Date Range` / `filter-Advanced Options`.
- [ ] `npm test` and `npm run typecheck` pass.
- [ ] No task-completion behavior is added in this task.
