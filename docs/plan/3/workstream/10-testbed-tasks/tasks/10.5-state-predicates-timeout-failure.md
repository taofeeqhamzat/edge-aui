# Task 10.5 — State Predicates, Timeout and Failure

## Description

Replace control-touch completion with testbed-owned state predicates and explicit lifecycle
semantics:

- define a narrow `TestbedTaskUiState` snapshot;
- implement the TD1–TD4 completion predicates and required evidence;
- implement a per-task timeout using `experiment.taskTimeoutsMs`;
- add `Failed` status and `task_fail` lifecycle for timeout;
- define abandonment reasons for reset, replacement, condition change and interruption;
- emit `task_complete` exactly once when the predicate passes.

## Acceptance criteria

- [ ] `TestbedTaskUiState` contains page, applied filters, visible row count, empty flag, current
      report ID, visited report IDs and last action evidence. It contains no free-text field values.
- [ ] TD1 predicate requires Analytics, Europe, 18 rows and a recorded export action.
- [ ] TD2 predicate requires dateFrom 2025-06-01, categories `[Books]`, 5 rows and Apply.
- [ ] TD3 requires an empty Apply state for Europe/Books/2025-09-01, then a clear-all that restores
      50 rows; clearing only one filter does not complete.
- [ ] TD4 requires both report IDs visited, `eu-books` active, the Books preset, 6 rows and export.
- [ ] Wrong values/reports/partial clears do not complete; completion is emitted once.
- [ ] Timeout produces `task_fail` with `Failed` and reason `timeout`; it does not produce
      `task_complete`.
- [ ] Reset/replacement/condition-change/interruption produce explicit `task_abandon` reasons.
- [ ] Fake-timer tests cover timeout, completion-before-timeout, reset, replacement and condition
      change.
- [ ] `npm test` and `npm run typecheck` pass.
