# Task 10.6 — Canonical Actions and Task Tests

## Description

Make one participant action produce one task-observable interaction, eliminate spurious
`task_error` on canonical paths, and add the integration/regression tests for TD1–TD4.

## Acceptance criteria

- [ ] Clicking a checkbox produces exactly one committed selection interaction, not
      `click` + `input` + `change` duplicates.
- [ ] Submitting Apply produces exactly one apply interaction; the preceding button click does not
      become a second interaction or error.
- [ ] Committing a date produces one date interaction; intermediate input events do not duplicate.
- [ ] Export produces one export interaction; it is not labelled as a form submit.
- [ ] Canonical TD1–TD4 paths complete with `errors === 0`.
- [ ] Wrong actions still produce a controlled `task_error`; the error count remains diagnostic.
- [ ] Task-start normalization, report preset application and programmatic route changes do not
      emit participant navigation actions.
- [ ] Tests cover checkbox, date, Apply, Export, report open and task-start routing.
- [ ] Existing observer tests and task tests pass; no raw event is deleted from the trace.
- [ ] `npm test` and `npm run typecheck` pass.
