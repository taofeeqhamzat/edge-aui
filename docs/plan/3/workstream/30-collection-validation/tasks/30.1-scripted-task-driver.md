# Task 30.1 — Scripted TD1–TD4 Driver

## Description

Rewrite the scripted browser harness to execute TD1–TD4 under both conditions against the real
runtime and export traces.

The driver must:
- start from a clean trial and the task's declared starting page;
- perform the canonical action sequence with real DOM events;
- wait for apply/settlement/lookahead rather than arbitrary sleeps only;
- record the trace and condition;
- assert the expected completion evidence and counts;
- label every capture `scripted`.

## Acceptance criteria

- [ ] `scripts/record_scripted_traces.py` supports `TD1`–`TD4` and `baseline`/`adaptive`.
- [ ] It no longer references T1–T3, `EMEA`, `Enterprise` or the removed segment control.
- [ ] TD1 asserts Europe/18 rows/export; TD2 asserts date+Books/5 rows; TD3 asserts 0→50 via reset;
      TD4 asserts both reports/Books/6 rows/export.
- [ ] The driver starts each task through the testbed task control, not by calling internal
      task-manager methods.
- [ ] A run fails loudly if the expected element/state is missing; it does not silently skip a
      step.
- [ ] Eight captures are produced (four tasks × two conditions) with `provenance: scripted`.
- [ ] Each capture is a 1.4.0 trace with semantic outcomes and task-definition version.
- [ ] A manifest records commit hashes, condition, task, timestamps, browser/viewport and result.
- [ ] The script exits non-zero if any expected completion fails.

## Verification

```bash
cd model-preparation
python3 scripts/record_scripted_traces.py --help
python3 scripts/record_scripted_traces.py --tasks TD1 TD2 TD3 TD4 --conditions baseline adaptive
```

The exact CLI flags may be adjusted during implementation; preserve the task/condition selection
and non-zero failure behavior.
