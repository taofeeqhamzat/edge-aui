# Task 30.2 — Trace Verification and Collection Readiness

## Description

Verify the scripted captures, update the trace verifier for schema 1.4.0/semantic outcomes, run the
acceptance matrix, and document the collection-ready state.

## Acceptance criteria

- [ ] `scripts/verify-trace.mjs` (or equivalent) accepts 1.4.0 traces, validates semantic
      outcomes/task version, and still reports legacy 1.3.0 limitations rather than failing them.
- [ ] The verifier checks: no orphaned windows outside the allowance; every prediction has a policy
      verdict; every applied episode is terminal; task completion/abandonment consistency;
      prediction→window attribution.
- [ ] `scripts/compare-condition-traces.mjs` distinguishes baseline zero-mutation from adaptive
      configured interventions for TD1–TD4.
- [ ] At least one real exported 1.4.0 trace ingests successfully in model-preparation; unknown
      schema versions still fail loudly.
- [ ] The acceptance matrix covers TD1–TD4 × baseline/adaptive, canonical counts, timeout, reset,
      duplicate actions and semantic outcomes.
- [ ] Collection readiness document records: provenance mode, session persistence, participant ID,
      Supabase configuration, export path, recovery behavior and remaining deferred study items.
- [ ] No scripted trace is described as participant evidence.
- [ ] The evidence report distinguishes verified, inferred and blocked items.
