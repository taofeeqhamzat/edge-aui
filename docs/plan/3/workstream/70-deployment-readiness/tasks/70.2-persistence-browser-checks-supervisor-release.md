# Task 70.2 — Persistence, Browser Checks and Supervisor Release

## Description

Verify trace persistence/export, session recovery and the Supabase provenance gate in the deployed
environment; record browser/environment checks; publish the supervisor demo runbook and honest
limitations.

## Acceptance criteria

- [x] A completed task session persists locally and exports a valid 1.4.0 trace (verified in `tests/trial_completion_upload.test.ts` and `tests/deployed_acceptance.test.ts`).
- [x] Session recovery behaves as documented; an interrupted session is reported, not silently merged (verified in `tests/collection_persistence.test.ts`).
- [x] The Supabase collection gate refuses participant-provenance upload in `scripted` mode and permits only the configured provenance; no service-role key is in the browser bundle (asserted in `tests/collection_persistence.test.ts` and `tests/check_deploy_assets_collection.test.ts`).
- [x] Baseline/adaptive runs are repeatable; trace condition/provenance/model version are correct (verified across TD1–TD4 runs in Workstream 30 & 60).
- [x] Browser/environment checks are recorded for the intended study browser; unsupported browsers are marked unverified (Chrome 157 verified; Firefox/WebKit marked `NOT MEASURED`).
- [x] The supervisor demo script covers TD1–TD4, baseline/adaptive, Reports comparison, trace export and model/provider status (documented in `release-report.md` §7 and `docs/deploy/verification-runbook.md`).
- [x] Known limitations, actual measurements and deferred items are documented (unmet 500 KB payload target under ADR-008/016, CLS and active memory `NOT MEASURED`).
- [x] Final acceptance matrix maps each requirement to evidence (test, screenshot, trace, manual observation) (`release-report.md` §2).
- [x] No participant-study claim is made; only engineering/reproducibility evidence is reported.
