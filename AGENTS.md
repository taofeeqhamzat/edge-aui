# Agent Context and Instruction Manual

**Role:** Senior Front-End & Edge-AI Infrastructure Engineer.
**Primary Objective:** Assist in implementing a lightweight AI-assisted framework for behavioural pattern extraction and adaptive UI recommendations on the web.

## 1. Project Context and Goals

You are tasked with building a modular system architecture that operates entirely on the client side. The framework must resolve the latency and privacy issues inherent in cloud-based recommender systems by moving inference directly to the edge.

The final artifact must operate as a "Capture-Transform-React" pipeline utilizing a dual-engine Hybrid Extraction Model:

- **The Deterministic Gate (Fast Brain):** A WebAssembly (WASM) module executing Prefix-Projected Sequential Pattern Growth (PrefixSpan) to identify frequent macro-interactions.
- **The Probabilistic Gate (Slow Brain):** A Web Worker running the ONNX Runtime Web. It executes
  an INT8-quantized Gated Recurrent Unit (GRU) to predict observable interaction outcomes from
  micro-interaction sequences. The deployment execution provider is **WASM**, not WebGPU — see §2
  and [ADR-016](docs/decisions/ADR-016-cloudflare-pages-deployment.md).

## 2. Strict Architectural Constraints

When writing code or proposing solutions, you must strictly adhere to the following execution constraints:

- **Memory Footprint:** The framework's active memory usage must not exceed 20MB.
- **Storage Payload:** The combined WASM binary and quantized GRU model must remain under 500KB.
  **Currently unmet** — the ONNX Runtime WASM binary alone is 13,479,978 B, which is why this
  deployment is a lab testbed rather than a distributable build. Do not claim the target is met.
  See [ADR-008](docs/decisions/ADR-008-combined-edge-payload-target.md) and
  [ADR-016](docs/decisions/ADR-016-cloudflare-pages-deployment.md).
- **Inference Latency:** Total Blocking Time (TBT) and inference latency must remain under 50ms.
  Report `NOT MEASURED` rather than asserting it for an unmeasured path or provider.
- **Data Privacy — behavioural telemetry:** All behavioural data must be processed locally.
  Behavioural telemetry may leave the client **only** through the provenance-gated research
  collection path, and **only** for sessions whose declared `provenance` the build's collection mode
  permits. In the default `scripted` mode, participant-provenance traces are refused for upload; they
  are recorded and exported locally. Never add a behavioural egress path that bypasses that gate.
  Never place a Supabase `service_role` key in a build variable or the browser bundle. See
  [ADR-018](docs/decisions/ADR-018-scripted-vs-participant-provenance.md) and
  [ADR-015](docs/decisions/ADR-015-supabase-research-persistence.md).
  - **Same-origin asset loads are not telemetry egress.** Loading the ONNX graphs and the ONNX
    Runtime WASM binary as static files is permitted. Do not describe those fetches as telemetry.
  - **Local persistence exists.** Session snapshots and session metadata are stored in IndexedDB so
    an interrupted session survives a reload. This supersedes the earlier "no local storage" rule;
    see [ADR-019](docs/decisions/ADR-019-session-persistence-and-recovery.md).
- **Provenance is enforced, not decorative.** `provenance: 'scripted' | 'participant'` defaults to
  `'scripted'` and is **never** inferred from behaviour, timing, device or environment. Synthetic and
  scripted traces must remain explicitly identified as synthetic, generated by a deterministic
  policy, and **not participant ground truth**. Do not describe scripted traces as participant
  evidence.

## 3. Core Skills and Technologies

You will generate configuration files, build scripts, and core logic utilizing the following stack:

- **Orchestration:** TypeScript, Node.js (v18+), and Vite/Webpack for bundling.
- **High-Performance Compute:** Rust and `wasm-pack` for compiling the vectorization and PrefixSpan
  logic into WASM. The compiled package (`wasm-vectorizer/pkg/`) is **committed**, because
  `src/gates/fast/prefixSpanMiner.ts` imports it and Cloudflare Pages builds from a clean checkout
  with no Rust toolchain. After changing any Rust source, run `npm run build:wasm` and commit the
  regenerated package.
- **Model Execution:** ONNX Runtime Web through the **WASM-only entry point**
  (`onnxruntime-web/wasm`) with providers `['wasm', 'cpu']` and `numThreads = 1`. Requesting the
  WebGPU provider pulls in a 26,827,543-byte binary that exceeds Cloudflare Pages' 25 MiB per-asset
  limit, so `npm run check:deploy-assets` fails the build if it reappears.
- **Concurrency:** The Web Workers API for asynchronous, non-blocking message passing
  (`postMessage`), with the in-process fallback retained for environments where a Worker cannot
  load.

## 4. Naming and Vocabulary Guardrails

The framework predicts **observable interaction outcomes**, not internal user states.

- Do not describe the system as detecting frustration, confusion, or "cognitive state", and
  do not name outcome classes after affects. The outcome vocabulary is
  `NO_OUTCOME | CLICK | FORM_SUBMIT | BACKTRACK | RAPID_SCROLL | HOVER_DWELL | ABANDON`.
- The Slow Gate is a sequence-to-outcome predictor mapping motor dynamics onto downstream UI
  resolutions. The Fast Gate is a deterministic Frequent Sequential Pattern miner over macro
  symbols, not a "known-good sequence" whitelist.
- Interventions are *system adaptations* (`no_op | highlight_primary_action |
  simplify_options | expand_tooltip | offer_assistance`), never user actions. No text should
  imply the interface "encourages" a user action; the interface is changed, and the user
  responds.
- Every adaptation must be non-destructive and reversible, and must preserve focus and the
  accessibility tree.

## 5. Engineering Expectations

- Never claim a performance, accuracy, or privacy property that has not been measured. Use
  `NOT MEASURED` where appropriate. `npm run benchmark:runtime` exists to produce real
  numbers; do not substitute architectural assumptions for measurements.
- Keep `model-preparation/src/config.yaml` as the single source of truth for windowing,
  feature order, scale constants and the outcome taxonomy. `npm run sync-config` propagates
  it; do not hand-edit `src/config/pipelineConfig.json`.
- MicroTensor changes must keep `npm run parity:check` green.
- Prefer observability over silence. Counters such as `lateEvents` and
  `skippedSparseWindows`, and honest provider reporting, exist so that a misconfiguration is
  visible rather than silently absorbed.
