# Edge-AUI Target Testbed

A browser-only research testbed for **behavioural pattern extraction and adaptive UI
recommendation on the web**. It is the target environment for the
[`edge-aui-model-preparation`](https://github.com/taofeeqhamzat/edge-aui-model-preparation)
pipeline: it passively observes interaction, reduces it to an 18-dimensional MicroTensor
stream, matches macro-interaction sequences deterministically and probabilistically, and
applies non-destructive interface adaptations — recording everything needed to replay and
evaluate the result offline.

Inference runs in the browser. Behavioural telemetry is **processed locally and does not leave the
client by default**: a completed trace is uploaded to the research collection store only when its
declared `provenance` permits it *and* the build is configured to collect (see
[Egress and provenance](#egress-and-provenance)). Session snapshots are held in IndexedDB so an
interrupted session survives a reload.

> **Status: v0.1 research deployment.** The intervention model's supervision remains **synthetic** —
> scripted browser sessions generated by a deterministic policy, **not participant ground truth**. No
> participant data has been collected and no participant study has been run. The deployment
> demonstrates an integrated browser-side adaptive UI research prototype with model inference,
> intervention execution, task instrumentation and persistent research-trace collection. It does not
> demonstrate participant usability, behavioural generalisation, intervention effectiveness, or
> production readiness.

## What runs

```
DOM events → TelemetryObserver → BehaviourEvent
                                    ├─ RollingWindowBuffer → 18-D MicroTensor (500/250 ms)
                                    ├─ OutcomeDeriver      → OutcomeEvent (lookahead [500,1500] ms)
                                    └─ MacroInteractionStream → symbol sequence
                                                                   │
                         worker: SequenceBuilder (T=8) ────────────┤
                                 │                                 │
                                 ▼                                 │
                      AdaptiveInferenceEngine                      │
                        ├── Fast Gate  (PrefixSpan over symbols, WASM)
                        └── Slow Gate  (INT8 GRU, ONNX Runtime Web, WASM)
                                 │
                                 ▼
                      InterventionPolicy → UIActuator → DOM (reversible, TTL-bounded)
                                 │
                                 ▼
                   ExperimentRecorder → canonical 1.3.0 trace
                                 │
                                 ├──► IndexedDB write-ahead (survives reload)
                                 └──► Supabase (provenance-gated)
```

Two experimental conditions are supported. In `baseline` the pipeline still observes, windows,
mines, derives outcomes and records predictions **and policy decisions**, but never mutates the DOM
— so the two conditions can be compared like for like, and the trace itself evidences "decided but
not applied".

Full details, including the windowing contract, feature table, macro vocabulary, gate
semantics, and every schema, are in [`docs/architecture.md`](docs/architecture.md).

## Egress and provenance

Every session carries a machine-readable `provenance`, which defaults to `scripted` and is **never**
inferred:

| Provenance | Meaning | Uploaded by default? |
|---|---|---|
| `scripted` | Synthetic/automated browser session | Yes |
| `participant` | Human, under an approved protocol | **No** — refused until a consent workflow exists |

`VITE_AUI_COLLECTION_MODE` selects what a build may upload (`off` \| `scripted` \| `all`). A build
with no Supabase configuration is fully supported: it records locally, exports traces as JSON from
the research panel, and reports `collection: local_only` instead of attempting an upload. See
[`docs/deploy/README.md`](docs/deploy/README.md) and
[ADR-018](docs/decisions/ADR-018-scripted-vs-participant-provenance.md).

## Requirements

- Node.js 18+ and npm
- A browser supporting WebAssembly for the runtime. The deployed execution provider is **WASM** (not
  WebGPU); see [ADR-016](docs/decisions/ADR-016-cloudflare-pages-deployment.md).
- `wasm-pack` and a Rust toolchain **only** to regenerate `wasm-vectorizer/pkg/`, which is otherwise
  committed as a build input.
- Supabase is optional and not required to run or verify the testbed.

## Getting started

```bash
npm install
cp .env.example .env.local     # optional: fill in Supabase values, or leave blank
npm run dev                    # http://localhost:5173
```

The application renders a small analytics dashboard. Use the **Experimental Trial** controls on the
Analytics view to start task T1/T2/T3 and to switch between the `baseline` and `adaptive` conditions.
The **AUI Debug** panel shows live session, condition, decision state (including *why* an intervention
did or did not occur), the active intervention episode and its TTL, model/provider provenance, mining
counters, eviction counts and collection state, and exports the experiment trace as JSON. In
development, `window.__EDGE_AUI__` exposes the same state programmatically. In a production build the
panel is reachable with `?auiDiagnostics=1` or by setting `VITE_AUI_DIAGNOSTICS=1`.

### Model artifacts

The Slow Gate graphs are committed at `public/models/model_int8.onnx` and
`public/models/intervention_head_int8.onnx` so the testbed runs and the ONNX contract test passes
without a model-preparation checkout. `*.onnx` is otherwise gitignored because model files are build
outputs; `public/models/` is an explicit exception.

To regenerate them from a trained checkpoint:

```bash
# in the model-preparation checkout
.venv/bin/python -c "from src.export import export_and_quantize; export_and_quantize()"
cp models/model.onnx models/model_int8.onnx /path/to/edge-aui-framework/public/models/
```

If an artifact is missing, the runtime falls back to a deterministic Slow Gate and reports the
downgrade in the console and on the panel — it does not silently pretend a learned model is running.

## Testing and verification

```bash
npm run typecheck           # tsc --noEmit
npm test                    # vitest run
npm run parity:check        # fail if the MicroTensor fixture diverges from the Python reference
npm run build:ci            # clean-clone build + deployment asset inventory gate
npm run check:deploy-assets # asset inventory only
npm run benchmark:runtime   # FPS, heap and inference latency, measured in a real browser
```

`npm test` runs `sync-config` first, which regenerates `src/config/pipelineConfig.json` from
`model-preparation/src/config.yaml`. The Python configuration is the single source of truth
for windowing, feature order, scale constants and the outcome taxonomy.

The suite includes `tests/deployed_acceptance.test.ts`, which runs the real pipeline with the real
INT8 ONNX graphs, asserts that the learned head actually served inference, and verifies the resulting
trace against the project's own verifier. What it **cannot** establish — a live Cloudflare Pages
origin and a live Supabase project — is recorded as `NOT VERIFIED` in
[`docs/deploy/verification-runbook.md`](docs/deploy/verification-runbook.md) rather than assumed.

## Service payload note

The combined WASM + model payload target of 500 KB (ADR-008) is **not met**: the ONNX Runtime WASM
binary alone is 13,479,978 B. This is a known, tracked deferment, which is why the current artifact
is a lab testbed rather than a distributable build. No performance claim in this repository should be
read as meeting that budget.
